# Routing quality and cost experiment

Run local validation with `./bench.sh --dataset challenge`. Without a model key this runs tests, graph checks, deterministic output-contract controls, and a dry routing experiment. A dry run leaves model-dependent tasks unresolved and cannot pass the model-comparison gate. `node bench/evaluate-local.js` performs the independent local conformance checks alone. `node bench/evaluate-local.js --outputs candidates.json` grades an array of `{ "id": "ev01", "output": { ... } }` generated artifacts against those four task contracts.

With an explicitly configured model key, `node bench/run.js --dataset challenge` runs the three arms sequentially. `--limit 2` selects a smoke subset from each domain and cannot pass a full-comparison gate. `--seed example` controls case shuffle and balanced arm rotation. `--max-turns 8` bounds the two model loops. There are no automatic whole-task retries. Adapter repair calls appear as separate provider requests. Do not run concurrent paid experiments against the shared cumulative ledger; its budget is shared and file replacement is atomic, but it is not a multiprocess transactional accounting service.

For actual Eve, install the isolated pinned experiment's dependencies with `npm --prefix bench/eve-runtime ci`. `node bench/run.js --dry --dataset challenge --eve-runtime --limit 2` verifies its actual client/runtime using explicit mock models; it cannot measure AI quality. With the configured Haiku 5.5 key, `node bench/run.js --dataset challenge --eve-runtime` replaces the simulation with the real Eve fixture. `--include-simulation` deliberately retains all four arms. Read `bench/eve-runtime/README.md` for its version, limits, instrumentation, and direct CLI verification. Runtime startup time is recorded separately from case latency; wrapper elapsed time is also preserved.

`node bench/evidence-models.js --mock --eve-runtime` exercises the real Wayfile scripts/schema skill, typed model loop, and actual Eve evidence client with mock outputs only. `node bench/evidence-models.js --eve-runtime --model anthropic/claude-haiku-5.5` performs the separate bounded generated-output comparison; `node bench/run.js --evidence-models --eve-runtime` is an equivalent entry point. All arms use the same explicit 800-token cap per provider request, eight-turn tool-loop limit, shared policy, immutable record service, and factual output/evidence grader. Wayfile's scripted reads form a customer → order → regional policy chain before its generation call. Case-specific expected decisions and summary diagnostics never enter model-facing inputs or tools. A correct JSON reply without actual versioned record reads or a required simulated approval fails the factual/evidence contract. `--limit 1` is a smoke check, not a full comparison. Schema repairs are charged; factual failures are scored without gold-derived repair feedback. These four tasks are public development cases, not an independent holdout or a production reliability estimate.

Each invocation writes a new `bench/results/<timestamp>-<dataset>-<id>/` directory with `manifest.json`, the selected `dataset.json`, append-only `requests.jsonl` and `cases.jsonl`, and `report.json`/`report.md`. Corpus, gold labels/contracts, source files, git commit, requested model/settings, actual per-response model/provider, arm order, cache regime, and per-run ledger deltas are recorded. Historical `docs/bench-2026-10-13.md` and results are never overwritten. The artifact's source-change flag prevents passing a comparison if files changed while it ran.

The primary metrics are **full contract success on the same cases** and **measured model API dollars per successful task**, where the numerator includes failed calls, malformed responses, and repair attempts. Route accuracy remains a separate diagnostic. A successful route can fail the task contract if a required lookup or approval is absent, the lookup facts are wrong, or lookup precedes mandatory approval. Zero-cost responses are valid measurements; missing costs stay unknown. Price-table estimates and token ratios cannot pass a gate. Local process costs, deployment infrastructure, human labor, and independent grading are currently unpriced, so this is not total production cost.

The observed quality gate uses paired task results, prevents a lost approval/missing-data task from being offset by an unrelated win, and requires nondecreasing success in each domain. It reports paired wins/losses, per-family results, p50/p95 latency, and dollars/success. A pass is an observed development/regression comparison against the named arms; an actual Eve pass requires its measured runtime arm. It is not a statistical noninferiority claim or evidence of unseen generalization. To make that claim, pre-register the allowed quality margin and weighting, use independently authored and adjudicated cases, and compute paired confidence intervals clustered by scenario family across repeated runs.

## Datasets and label limits

The hand-label process and its same-author limitations are documented in [LABELING.md](LABELING.md).

`legacy` preserves the historical 70 labels: 50 support tickets are five repetitions of ten templates, and the twenty CI cases are hand-authored. These are regression cases. Some legacy test-failure labels infer causality from a changed filename with no diff or causal evidence; model agreement cannot repair that underdetermination. Version 2 adds evidence contracts and explicit approval observation, so its full-success metric is not interchangeable with the historical endpoint-only score.

`challenge` is a new public **development** set with paraphrases, conflicting intents, negation and quoted mentions, missing/invalid fields, approval denial, boundary values, and CI causal evidence. It is intentionally available for tuning and must not be called an unseen holdout. The four separate evidence tasks resolve a customer → order → regional policy chain, including a missing order and denied approval. Their primary generated JSON contract checks structured facts/reasons, exact evidence-source versions, actual reads/approval, schema and summary bounds. Completed-payment claims and prose contradictions are diagnostic warnings requiring semantic adjudication. The local conformance suite uses explicit reference fixtures, corruptions and separate diagnostic expectations; its pass count measures the validator/diagnostics, not an AI model's task quality.

Generated evidence now uses **output contract V2 and grader V4**, with the same public task corpus V1, unchanged schema and policy. The primary metric is **factual/evidence contract success**: valid JSON Schema, exact structured reason/decision/amount/currency, exact source versions, actual reads and required approval, and a nonempty bounded summary. Every arm receives amount `number|null`, currency `string|null`, and a required policy `reason_code`. This metric does not measure free-form prose faithfulness or overall generated-reply quality.

English prose heuristics remain visible under `proseDiagnostics`, outside the primary checks. They have known false positives and false negatives and never determine automatic wins/losses. Every result sets `proseFaithfulnessMeasured:false` and `proseAdjudicationRequired:true`, including results with no heuristic flags. Adversarial controls still verify warnings for unsupported completed payments, contradictory approval, and vague prose; regression tests also expose a valid “no such order was found” false positive and an unsupported “refund settled yesterday” false negative. A bounded unblinded manual audit is a separate development observation, not an independent semantic-quality certification. Independent semantic adjudication is required before claiming preserved prose faithfulness.

The original V1 paid generated-output report is preserved, including its NO-GO. Its amount property lacked a JSON type, which permitted strings under JSON Schema; native Eve forwarded that schema unchanged. Its summary grader also required exact words and rejected factual equivalents. Those are fixture/grader defects, so the V1 arm success rates cannot establish relative runtime quality. V2 reports have distinct versioned directories and metadata; V1 and V2 full-success scores are not interchangeable. Changes followed public development feedback and do not create an unseen holdout.

Grader V3 previously corrected a coordinated-negation false positive, then a fresh development run exposed another valid summary flagged as contradictory. V4 ends authoritative English-pattern grading rather than adding more phrase exceptions. `node bench/evidence-regrade.js ORIGINAL_REPORT_JSON [--audit AUDIT_JSON]` applies the defined factual/evidence metric offline to identical captured outputs and evidence, copies the original request journal, and retains original calls/costs/provenance in a new directory. It verifies archived corpus, factual-label and output-schema hashes and preserves the original report/gate. Regrades are marked **post hoc development metric/grader corrections**, with zero new calls/spend; they are not fresh or independent comparisons. A manual audit can annotate prose concerns and adjudicate diagnostic false positives without changing automated contract scores. Original G3 full-success and G4 factual/evidence success are different metrics and must be labelled separately.

The record's `ageDays` denotes order age. Delivery status provides no delivery date. The shared policy now states this explicitly after review found outputs equating order age with time since delivery. Regrades do not retroactively penalize that inference under the clarified policy; audits disclose it. A new matched run after freezing this clarification is a further public development experiment, not an independent holdout.

`node bench/label.js --dataset challenge` is an optional, separately charged agreement diagnostic. It keeps labels fixed and reports disagreements for human adjudication. Same-model agreement is not independent gold. `bench.sh` does not repeatedly pay to re-label an unchanged corpus.

For a genuine held-out study, freeze all graph, prose, tool, repair, and model settings before a different author creates a private challenge pool. Split by scenario/template family rather than by ticket row or paraphrase. Keep labels and rationale files out of model-facing resources; allow runtime access only to policy and fixture evidence. Use separate development and final pools, hash the final corpus before execution, disclose any exposures, and reserve another unopened pool when tuning follows a failure. Include actual not-found order records, stale/changed policy evidence, conflicting sources, tool failures, multiple failing tests, and generated replies in that final study.

## Cache and spend accounting

Provider cached reads and writes remain separate token counters. They have different prices and are not equivalent to uncached input or output. Actual account charges are preferred; [OpenRouter usage accounting](https://openrouter.ai/docs/cookbook/administration/usage-accounting) distinguishes account charge from upstream inference cost. The per-call journal captures costs before downstream validation can fail. A response-decoding failure can recover a positive paid ledger delta, while unavailable token/model provenance keeps the comparison incomplete.

Wayfile's application memo is disabled in the routing experiment. Provider caching is observed, not experimentally cold or guaranteed warm. The previous run called arms in a fixed order and reported a cumulative ledger as “this run”; the new report separates these values. For cache claims, run separately randomized cold and steady-state experiments with provider-supported cache controls, declared warm-up cost, realistic duplicate frequency, fixed cache lifetime, and all seed/replay spend in the numerator. Exact-input memo reuse must use source/evidence revisions in its key and must not give Wayfile gold-labelled responses unavailable to the other arms.

## Actual Eve comparison and remaining work

Paid matched development runs against the pinned actual Eve fixture are recorded in [the current evidence report](../docs/bench-quality-2026-10-13.md). The original routing run and revised policy rerun remain separate, and the flawed V1 generated-output experiment is preserved with its diagnosis. These observed measurements do not settle unseen quality or the cost frontier for optimized production workflows.

The `eve_sim` arm is a hand-written eight-turn model loop with skill-description disclosure and a bash tool. It does **not** load or execute Eve. Its instructions and skills are authored for this experiment. The bash arm is likewise a hand-written model loop, not an optimized deterministic shell router. Neither establishes a cost advantage over an optimized production competitor.

Official Eve documentation describes [on-demand skills](https://eve.dev/docs/skills), [typed tools](https://eve.dev/docs/tools), [context controls](https://eve.dev/docs/concepts/context-control), [automatic prompt caching and model settings](https://eve.dev/docs/agent-config), and a [durable default harness](https://eve.dev/docs/concepts/default-harness). Its [eval assertions](https://eve.dev/docs/evals/assertions) can check structured output, tools, approvals, and event order. The simulation models only one of those architectural choices. Eve also permits authored deterministic workflows and tools; it need not consume a model call for every deterministic application action.

The optional `bench/eve-runtime/` package now pins Eve and its provider SDK independently of Wayfile's zero-dependency package. Its authored fixture uses real typed tools, skills, the official client, and a provider proxy that journals actual HTTP usage including failures and extra SDK calls. Local mock/protocol checks are separate from paid comparisons. A paid run must preserve matched model, provider route, settings, evidence and output limits; actual provider/model fields and incomplete-cost flags govern its report. An observed pass applies only to these fixture configurations. Comparing an additional reasonably optimized authored Eve workflow, genuine unseen task quality, interrupted-work durability, and total production/infrastructure cost remains outstanding. Mock fixtures cannot establish actual model accuracy or dollars per successful task.
